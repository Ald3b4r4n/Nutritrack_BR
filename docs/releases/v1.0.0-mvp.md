# Release Notes: v1.0.0-mvp

**Data:** 2026-05-21
**Status:** Validado e Aprovado

O MVP do NutriTrack BR atende todos os requisitos arquiteturais e funcionais levantados no escopo inicial (`specs/001-nutritrack-mvp/spec.md`). Foi priorizada uma experiência **offline-first** e de **privacidade**, salvando os dados no próprio dispositivo do usuário.

## Funcionalidades
- **Diário alimentar**: Adição de alimentos (Café, Almoço, Jantar, Lanches), com cálculo de macros.
- **Busca/Cadastro**: Fontes TBCA, USDA e customizada via texto ou Barcode.
- **Água**: Registro de hidratação (atalhos +200, +300, etc).
- **Peso**: Histórico e tendências.
- **Planos alimentares**: Templates base ativáveis por dia da semana.
- **Dashboard**: Resumo interativo de progresso com os atalhos de ações do usuário.

## Garantia de Qualidade

- **Análise estática (Lint)** totalmente limpa (`0 issues`).

## Pendências Pós-MVP e Riscos Técnicos (Dívida Técnica)
Para evoluções futuras (v1.1+), os seguintes pontos precisam de atenção:
1. **Assets Finais Nano Banana:** Ícones e imagens reais placeholders (como `empty_diary` e `water_drop`) devem ser substituídos ou inseridos.
2. **Gráficos Avançados:** O histórico de peso requer plotagem avançada (ex: package `fl_chart`).
3. **FTS5:** A busca de alimentos pode evoluir para SQLite FTS5 avançado para suportar typos, caso o seed base do TBCA/USDA seja incluído e atinja > 10.000 itens.
4. **Sincronização em Nuvem:** Implementar conexão com servidor caso backup ou auth sejam requisitos.
5. **Base TBCA/USDA Completa:** Empacotar seed inicial (`.sqlite` pré-carregado).
6. **Mobile Scanner KGP:** Resolver ou acompanhar o aviso sobre o uso de Kotlin Gradle Plugin (`KGP`) pela biblioteca `mobile_scanner`, que pode quebrar a compilação em versões futuras remotas do Flutter (ex: 4.x+).
